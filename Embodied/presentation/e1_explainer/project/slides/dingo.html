DINGO Algorithm 1 (p. 6)On the box grammar (E1)
Init: W[0, q0] = 1Every box block starts at <box>
Best-token transition V_i(q → q′)c-edge: best of the 1001 coordinate tokens. Fixed edge: P(that token)
W[i, q] = max over q′ of W[i−1, q′] · V_iOnly one q′ per state, so W = product along the path (we sum log-probs: same winner)
q_max = argmax over live states of W[d, q]At slot 6 the live states are exactly the 3 ★: pick the best template
Backtrack the parentsEmit that template with its chosen coordinates

Not from DINGO:

✚ Gate P(<box>) ≥ 0.6: labels and end lie outside the grammar

✚ No “no valid string” exit: zero probs floored at 1e-12

✚ The uncertain-coordinate rule afterwards is the release's

Because the grammar is a tree, DINGO's DP collapses to: score 3 paths, keep the best.

5 / 7

Left: the box grammar as an automaton with 15 states. Columns are window slots 0 to 5 from frame 2. A box block is box-start, four coordinates, box-end; a point is box-start, two coordinates, box-end, null, null; an empty box is box-start, none, box-end, null, null, null. c means any of the 1001 coordinate tokens. Every state has exactly one incoming edge, so the grammar is a tree. Right: DINGO's Algorithm 1 line by line. The best-token transition becomes: best coordinate for c-edges, the fixed token's probability otherwise. The max over predecessors is trivial with one predecessor, so W is the product along the path; summing log-probabilities picks the same winner. At slot 6 the only live states are the three accepting ones, so DINGO picks the best template, and backtracking emits it. In the code slot 0 is not added to any score: it is the same box-start on all three paths. Three things are ours, not DINGO's: the 0.6 gate, no no-valid-string exit (probabilities floored at 1e-12), and the release's uncertainty rule afterwards.
